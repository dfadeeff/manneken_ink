# Mika

An AI personal tutor for children in the 2nd to 4th class (~7–10 years old), covering
**maths and German**. Parents own the account and add one profile per child; each child
gets their own tutor that hints before it answers and never shames a wrong attempt.

There is no landing page. You arrive at a prompt box; the first prompt asks you to sign in
and is replayed for you afterwards, so nothing has to be typed twice.

## Design principles

Two rules shape most of the code:

1. **The model never has the last word on whether a child is right.** Maths items are
   generated and checked in Python; grading is a ladder of exact match, then normalised
   match, and only falls back to a model judge for open text. An LLM that marks a correct
   answer wrong does real harm to a 8-year-old's confidence.
2. **Guardrails are deterministic wherever they can be.** Rate limiting, hard safety
   signals, and prompt-injection containment are plain Python that nothing typed by a
   child — or generated by a model — can argue its way past.

## Architecture

```
frontend/     Next.js 16 · React 19 · Tailwind v4 · Clerk        → Vercel
backend/      FastAPI · SQLAlchemy 2 · Alembic · Postgres        → Railway
```

### Guardrails

Five layers, applied in order. Layers 1, 2 (its deterministic half) and 5 need no model.

| # | Layer | Where |
|---|-------|-------|
| 1 | Rate limit, length cap, daily cap | `app/tutor/guardrails.py` |
| 2 | Safety triage: hard signals first, model second | `app/tutor/guardrails.py` |
| 3 | The tutor constitution (system prompt) | `app/tutor/prompts.py` |
| 4 | Output validation: contact details stripped, reading level checked | `app/tutor/guardrails.py` |
| 5 | Injection containment: child input fenced as data | `app/tutor/guardrails.py` |

Distress and unsafe messages never reach the tutor model. They get a fixed, non-generated
reply that points the child at a trusted adult and makes no attempt to counsel, and they
write a row to `safety_flags`.

Streamed replies pass through `StreamSanitiser`, which releases only whole
whitespace-delimited tokens — so a URL can never be half-emitted before the cleaner sees it.

### Model routing

Call sites name a **task**, never a model. Tasks map to a tier, tiers map to an ordered list
of candidates in `app/llm/registry.py` with their real per-million-token prices:

| Tier | Used for | Default first choice |
|------|----------|----------------------|
| `fast` | safety triage, answer normalisation | `claude-haiku-4-5` |
| `standard` | tutoring dialogue, exercise generation | `claude-sonnet-5` |
| `strong` | word problems, open-text grading | `claude-opus-5` |

`ROUTER_POLICY` re-sorts each tier by `cost`, by `speed`, or leaves the declared preference
(`balanced`). Anthropic, OpenAI and Gemini are all supported; only the providers whose keys
are set are considered, and a failure falls through to the next candidate. Every call —
streamed calls included — records tokens, price and latency to `llm_calls`.

Re-pointing a tier is one line in `registry.py`, or `ROUTER_TIER_OVERRIDES` in the env.

### Data model

`parents` → `learners` → `chat_sessions` → `messages`, plus `exercises`/`attempts`,
`topic_mastery`, `safety_flags` and `llm_calls`. Every learner-scoped query goes through
`owned_learner()`, which checks the learner against the authenticated parent.

## Local development

### Prerequisites

- Node.js 18+, Python 3.11+
- A Clerk application (`NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY`)
- At least one model provider key: Anthropic, OpenAI or Gemini

```bash
cp backend/.env.example backend/.env
cp frontend/.env.local.example frontend/.env.local
# fill in the keys, then
./run.sh
```

Backend on `:8000`, frontend on `:3000`. `GET /api/config` reports which providers are
live and which model each task would currently route to.

`DATABASE_URL` defaults to a local SQLite file so the stack runs with no database to
install; point it at Postgres for anything real.

### Tests

```bash
cd backend && ./venv/bin/python -m pytest tests/ -q
```

The guardrail suite is deterministic and makes no model calls.

## Environment variables

### Frontend (Vercel)

| Variable | Description |
|----------|-------------|
| `NEXT_PUBLIC_API_URL` | Backend URL |
| `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` | Clerk publishable key |
| `CLERK_SECRET_KEY` | Clerk secret key |

### Backend (Railway)

| Variable | Description | Default |
|----------|-------------|---------|
| `DATABASE_URL` | Postgres (`postgresql+asyncpg://…`) | local SQLite |
| `CORS_ORIGINS` | Comma-separated allowed origins | `http://localhost:3000` |
| `CLERK_PUBLISHABLE_KEY` | Used to derive the JWKS URL | — |
| `CLERK_SECRET_KEY` | Clerk secret key | — |
| `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` / `GEMINI_API_KEY` | At least one required | — |
| `ROUTER_POLICY` | `balanced`, `cost` or `speed` | `balanced` |
| `ROUTER_TIER_OVERRIDES` | JSON, e.g. `{"standard": "google:gemini-3.7-flash"}` | — |
| `DEV_AUTH_BYPASS` | Skips Clerk; refuses to start unless `ENVIRONMENT=development` | `false` |
